## Problem Statement
An insurer's deterministic pipeline pulls 43 data sources and the BRE routes most proposals to AUTO-ISSUE / HARD-DECLINE / HARD-REFER. A residual set lands in GREY-ZONE, where the risk lives in the *relationship between facts* (comparison-shopping vs cover-stacking; thin-file vs concealment; a stale prescription vs an active undisclosed condition) — something a single deterministic rule structurally cannot judge. The agent is a 4-stage pipeline (BRE hands over named ambiguous flags → one `GreyZoneJudge` LLM call rules each flag from a closed set → a deterministic decision table gathers ≤1 piece of evidence and re-judges at most once, hard cap 2 calls → a deterministic grounding gate verifies every cited fact resolves). The model never emits the verdict; AML/pricing/hard-gates are unreachable by construction.

The question this session validated is NOT "is the engineering sound" (it is — it's a disciplined, production-shaped design). It is: **is this agent, sold as a standalone product, worth building for v1, and what is the narrowest wedge?**

## Demand Evidence
**None yet — conviction from research (founder's own answer, D1).** No insurer, no risk/underwriting leader, no pilot, no LOI. The founder chose the honest zero over "warm conversations." The ₹15,100 cr (FY24) / ~₹26,000–30,000 cr (FY25) repudiation figures prove the *problem* is real; they do not prove a buyer will pay *for this agent, this way*. Closing this gap is the assignment.

## Status Quo (the real competitor)
Every insurer already has a **manual referral queue**: cases the STP engine can't auto-decide get kicked to a human underwriter. That queue costs underwriter-hours, adds days of TAT (lost conversions), and lets non-disclosure slip through to contested claims. "Do nothing" for the buyer = keep staffing that queue. This — not Artivatic — is what a v1 sells against.

## Target User & Narrowest Wedge
- **Buyer:** an insurer's Head of Underwriting / Chief Risk Officer (owns loss ratio + repudiation exposure).
- **Wedge (corrected across the session):** NOT "AI underwriting for insurers" (occupied — see Competitor Landscape). NOT a customer *segment*. The narrowest wedge is **ONE insurer's ONE grey-zone referral queue**, co-built as a paid design partner, where the agent plugs behind the engine they already run and the deliverable is: (a) measurable referral-queue reduction, and (b) a contestability-grade audit trail per decision (the grounding gate productized). You exit owning a labeled "claim master" no competitor has.

## Constraints
- **Non-negotiable architecture (from CLAUDE.md):** staged pipeline, not a ReAct loop; evidence-gathering actions triggered by the deterministic decision table, never chosen by the LLM; agent never touches AML/PEP/STP-gate/identity-fraud/pricing; `final_verdict` produced by deterministic code, never the model; every cited fact grounding-checked; DSPy history retention + response caching OFF in prod; cheap model first; underwriting thresholds are placeholders pending the real manual.
- **Data-sparsity ceiling:** as a *vendor* you cannot compel evidence. ABHA person-linkage ~15% (0.28% worst case), Account Aggregator <10%, ~5 of 25 researched scenarios usable at scale. The flagship "catch hidden PED via ABHA" story is NOT deliverable at scale on the vendor path; queue-reduction + auditability is.
- **Regulatory tailwind (Aug 2026):** IRDAI crackdown — FY25 ~₹26–30k cr disallowed, 8% of 3.26 cr claims repudiated, mandatory 15-day settlement (Mar 2026) with penalties. Raises the value of *defensible, auditable onboarding decisions* over "catch more fraud."
- **Regulatory gate on the MGA path:** holding insurance risk needs an IRDAI insurer license (₹100 cr min paid-up capital). The realistic "become the underwriter" version is a carrier-partnered underwriting-manager / risk-sharing deal, not a self-held license.

## Approaches Considered
### Approach A: Design-partner wedge (RECOMMENDED)
Land ONE insurer as a paid design partner for their grey-zone referral queue. They bring the upstream they already own + historical grey-zone cases (your eval seed) + a reference logo; you bring the agent (already spec'd). Prove queue-reduction % + auditable trail on their real book. Effort S (human: weeks of BD + integration / CC: agent already spec'd). Risk Med (landing the first insurer). Reuses: the entire existing spec.

### Approach B: Eval-engine as the product
Make the labeling + regression + benchmarking harness the core product; the Judge is its output. Sell a grey-zone judgment that measurably improves on each insurer's book — un-rebuildable because they lack the cross-book corpus. Effort M-L. Risk Med-High (cold-start: needs a seeded book — i.e. needs Approach A first). Best as phase 2, not the opening move.

### Approach C: MGA / risk-selection-as-a-service
Carrier-partnered underwriting-manager for one underserved segment (self-employed thin-file); you own distribution + risk-selection + outcomes; the agent is internal edge; you generate labeled claim outcomes directly. Dissolves the data-sparsity problem (you can compel a PPMC). Effort XL. Risk High, capital- and regulatory-gated. A "what company do I want to run" decision, not a product decision.

## Recommended Approach
**Approach A.** It attacks the two fatal gaps simultaneously — D1 (no demand: you cannot land a paid design partner without real demand) and D4 (no moat: you exit owning the labeled eval set). It is the cheapest and fastest to proof, reuses the agent as-is, and keeps B and C open as futures. B is dominated as a first move (empty engine without A's seed); "build the agent as spec'd with no partner" is strictly dominated by A (same build, minus demand + data validation).

**The one deciding question that could override this:** do you want to build a software company or an insurance company? Software → A now, B later. Insurance → C, eyes open. There is no version where building the standalone agent product first, with no partner and no data, is correct.

## Improvement Roadmap (operative plan — founder's chosen path: build + sell the agent)
Goal restated by founder: cover more use cases + higher accuracy, competitively. Warning: do NOT copy incumbents' breadth (Artivatic = full platform, all lines, 10 insurers) — breadth is their strength and your death. Copy their accuracy *discipline* (data + feedback loop) on a narrow surface. What wins the first insurer is a believable accuracy number on *their own book*, not a feature list. Priority order:

1. **Eval set IS accuracy — build it before any new feature.** No accuracy without measurement; no measurement without underwriter-labeled grey-zone cases + expected rulings (the "claim master" per §6.4/§10/CLAUDE.md). This is also how competitors get accurate (more labeled data + tighter miss→relabel→re-optimize loop, not a smarter model) AND the only accuracy claim a buyer believes ("X% concordant with your senior underwriters on your own historical cases"). MIPROv2/GEPA are dead weight without it. First build task: labeling + regression harness, seeded with the 5 scenario fixtures, grown on every mishandled case.
2. **Cover the use cases that FIRE, not the ones that demo well.** Data-sources doc ranking stands: ~5/25 fire at scale, ~12 for a data-rich minority, ~8 weak. Deepen the firing set (velocity/mobile #10, facial BMI/smoking #4, PEP-on-nominee #21, IIB detection #12, disease-outbreak #8) + minority-segment ones the buyer's data supports. Rule: map every new `flag_type` to a data source that fires BEFORE building its ruling.
3. **Cross-flag reasoning — the one real edge over a rule engine.** Thesis is "risk lives in the relationship between facts" (scenario 24). §10 token-hygiene (per-flag slices) pulls against this. Add a "flag group" concept: correlated flags get ONE joint ruling with shared context. This is where the LLM earns its cost.
4. **Calibrated confidence, not the model's self-report.** Grounding gate is binary today. Add an empirically calibrated confidence band per ruling (calibrated vs the eval set, never the model's self-reported certainty); route low-confidence to escalate. Raises precision without blindly raising escalation. `confidence_band` exists; calibration is the work.
5. **Per-flag-type model routing (accuracy per rupee).** §8 open. Start cheap (Gemini Flash Lite-class), measure concordance per `flag_type` on the eval set, escalate model only for flag_types the cheap model botches. Holds accuracy while keeping "cost per case << human cost."

**Scope boundary:** #2 (new `flag_type`s) requires the BRE to emit them — upstream of the agent, a dependency to coordinate, not designed inside the agent. #1, #3, #4, #5 live entirely inside the agent (in scope).

## Improvement Roadmap — Detailed Design (deep dive)

### D1. The accuracy metric (build first — defines everything downstream)
Errors are asymmetric; a single accuracy % misleads. Track a triad:
- **False-benign rate** — underwriter-flagged cases the Judge waved through as `benign_explained`. Catastrophic (missed non-disclosure → repudiation). THE number insurers buy on. Drive to ~0, hardest on `non_disclosure_signal` / `needs_medical_check`.
- **Over-escalation rate** — underwriter-pass cases the Judge escalated/gathered. Safe but costs conversion + underwriter time. Keep bounded.
- **Grounding-hallucination rate** — how often the model cites evidence that doesn't resolve (gate blocks at runtime; measured in eval as model quality).

Labeled case shape: `{evidence_bundle, ambiguous_flags, follow_up_observations?}` → `expected_rulings:[{flag_id, ruling, must_cite?}]` + `expected_outcome`. Label = underwriter's ruling from the closed set. Sales/optimization line: *"On N cases: false-benign X%, over-escalation Y%, cost/case ₹Z."*
Cost matrix: penalize `needs_*`/`escalate` → `benign_explained` confusions far more than the reverse. Optimizers (MIPROv2/GEPA) and calibration both target this matrix, not raw concordance.
**Cold-start:** hand-label synthetic cases (5 scenarios = seed) from the underwriting manual to stand up the rig + baseline before any partner data; real cases replace synthetic as they arrive. Without this set, the optimizers are inert.

### D3. Flag groups (cross-flag reasoning — the rule-engine-proof edge)
Add one optional field; no new ruling type:
```python
class AmbiguousFlag(BaseModel):
    flag_id: str; flag_type: str; related_rule: str; context: dict
    correlated_with: list[str] = []   # sibling flag_ids the BRE marks jointly interpretable
```
BRE populates `correlated_with` for jointly-interpretable flags (it already knows which rules co-fired). Judge instruction gains: *"If a flag lists `correlated_with`, weigh those flags' evidence together; a combination may warrant a stronger ruling than either alone."* Send the UNION of correlated slices (bounded, honors §10 token hygiene; keep groups 2-3). Two individually-benign flags can jointly map to `needs_medical_check` within the existing closed set. Grounding gate unchanged (now validates cross-flag citations). Highest-value eval labels = combination-dependent correct answers (scenario 24 template) — exactly what a rule engine can't produce. Risk: over-correlation (model invents a link); guarded by calibration (D4) + the gate + small group size.

### D4. Calibrated confidence (empirical, not self-reported)
1. Raw score via **self-consistency**: sample Judge K=5 at temp>0, modal ruling, agreement fraction as raw score (model-agnostic, DSPy-friendly; Kx cost only on already-rare grey-zone cases).
2. **Reliability binning** on the eval set: empirical accuracy per agreement level (e.g. 5/5→97%, 4/5→88%, 3/5→62%).
3. **Per-flag-type thresholds** from the cost matrix (non-disclosure strict ~98%; occupation ~90%).
4. Plug into the existing deterministic gate (stays deterministic — map + thresholds are fixed artifacts):
```python
if calibrated_conf(r) < THRESHOLD[r.flag_type]:   # TODO(underwriting-manual): per-flag thresholds
    return escalate(reason="low_calibrated_confidence")
```
Sellable claim: *"we escalate the bottom N% by calibrated confidence and catch M% of what human review would."* Re-fit the map on any model/prompt/optimizer change (cheap; cached eval set).

### D2. Flag-taxonomy expansion — only where a source FIRES
New `flag_type`s map to EXISTING rulings (grow flags fast, ruling set almost never). Best firing candidates: `facial_declaration_divergence` (#4, fires ~100%), `cover_stacking` (#10 velocity/device, at scale). Each needs all three before building: (1) BRE emits it (upstream dependency), (2) a decision-table action or benign path, (3) labeled eval cases. **Boundary:** PEP-on-nominee (#21) is AML-adjacent → HARD-REFER in the BRE, NOT a grey-zone flag; keep out of the agent by construction.

### D5. Model routing — per-call by hardest flag present
Lookup `{flag_type → min_model_tier}`; call uses `max(tier)` over present flags. Measure concordance-per-flag_type on the eval set with the cheap model first; escalate model only for the flag_types it botches (likely cross-flag correlation + non-disclosure judgment). Preserves "cost per case << human cost."
